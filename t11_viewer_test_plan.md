# Минимальный план проверки viewer на одном предмете

Статус: план на будущий тест. В этой задаче viewer не скачивался, не запускался, а клиент не открывался через сторонний просмотрщик.

## Цель и границы

Проверить, способен ли кандидат читать файлы клиента `E:\Games\WoW_3.3.5_12340` (build 12340) и корректно показать один существующий item-прототип, его модель/текстуры и экипировку на персонаже. Тест не должен менять клиент, сервер, DBC, MPQ, SQL или базу; не извлекать файлы; не запускать игровой сервер; не создавать патчи.

До начала теста требуется отдельное разрешение на получение/запуск стороннего бинарника и закрытие риска из открытого issue `Any asset = crash`. Настоящий запрос такого разрешения не содержит.

## Контрольный объект

Использовать один уже задокументированный кандидат из `visual_candidates.csv`:

- `Netherblade Facemask`, Item ID `29044`;
- исходный набор `Netherblade`, ItemSet ID `621`;
- слот `Head`, DisplayID `45810`;
- поля записи кандидата указывают `Helm_Leather_RaidRogue_D_01.mdx`, текстуру модели `Helm_Leather_RaidRogue_D_01` и DBC texture-поля.

Эти значения служат только ключом теста, не подтверждением визуальной корректности. В самом реестре исходный кандидат не помечен визуально проверенным; loose-файлы не подтверждены, MPQ не просматривались.

## Предварительные условия

1. Решить вопрос происхождения: точный commit, источник бинарника, доступность исходников, checksum/Authenticode и связь бинарника с исходниками. Если это невозможно, тест не начинать.
2. Разрешить конкретную версию/артефакт и его запуск. Не брать EXE из неофициальных зеркал.
3. Подготовить отдельный sandbox-каталог внутри `C:\WOWServer 3.3.5\T11-Audit`, например `viewer-sandbox`, только после отдельного разрешения на запись туда. EXE не класть в клиент.
4. Снять штатными средствами перечень файлов и SHA-256 клиента, которые используются для проверки неизменности: как минимум `Wow.exe`, перечисленные целевые DBC и MPQ-файлы из `Data`. Хеши не изменяют содержимое. Зафиксировать время/состояние до теста.
5. Подготовить наблюдение за файловыми операциями средствами ОС, если они уже установлены. Ничего не устанавливать. Зафиксировать попытки записи/создания файлов в клиентском каталоге.
6. Не включать функции export/extract, bulk extraction, Noggit-интеграцию или любые действия изменения архивов.

## Шаги теста

1. Запускать EXE из `T11-Audit\viewer-sandbox`, чтобы все пути, которые README обещает «рядом с EXE», создавались только в sandbox.
2. Выбрать корень клиента `E:\Games\WoW_3.3.5_12340` и дождаться индексации. Не менять файлы клиента и не добавлять patch-папки.
3. Проверить, что загрузка не создаёт/не изменяет файлы в клиентском дереве. При первой попытке записи в клиент — сразу завершить тест, сохранить журнал наблюдения в sandbox и считать read-only требование не пройденным.
4. Попробовать найти item по Item ID `29044`. Если viewer не поддерживает поиск предмета по ID, проверить предусмотренный интерфейс поиска по DisplayID `45810`/имени модели. Не подменять объект с похожим названием.
5. Если ItemDisplayInfo интеграция доступна, зафиксировать, какие поля DBC он разрешил и откуда. Сопоставить со строкой `visual_candidates.csv`: Head, DisplayID, имя модели и текстурные поля. Если viewer показывает только модель по имени файла, отметить связку item→DisplayID как неподтверждённую.
6. Показать шлем на персонаже подходящей модели тела. Проверить видимость/скрытие шлема, геосет, текстуры, прозрачность и отсутствие отсутствующих ресурсов. Сохранить один скриншот через viewer только в sandbox.
7. Повторно снять SHA-256 тех же файлов клиента и сравнить с исходными. Любое изменение — тест немедленно не засчитывается, клиент не «чинить» в рамках аудита.
8. Завершить тест. Runtime-файлы (`cache`, `logs`, crash dumps, `screenshots`, `settings.ini`, `favorites.json` и т.п.) должны находиться исключительно в sandbox. В отчёте записать фактический список.

## Критерии результата

- **PASS, техническое чтение**: viewer загрузил MPQ/DBC для build 12340 без ошибок и без записей в клиент.
- **PASS, связь данных**: именно Item ID 29044 разрешился через фактический DisplayID 45810 и ожидаемые DBC-поля. Иначе связь UNVERIFIED.
- **PASS, визуальная проверка**: предмет отображён на персонаже, геосет и текстуры корректны; скриншот и заметка подтверждают конкретную конфигурацию. До просмотра статус остаётся UNVERIFIED.
- **FAIL**: падение, неверные/отсутствующие ресурсы, запись в клиент, несоответствие отображения или невозможность проследить item-to-display связь.
- **INCONCLUSIVE**: viewer умеет открыть модель по пути, но не показать item/слот или не раскрывает происхождение использованных DBC-значений.

Результат применим только к проверенному бинарнику, commit, конфигурации клиента и одному объекту. Он не доказывает совместимость всех предметов/геосетов или других сборок WoW.
