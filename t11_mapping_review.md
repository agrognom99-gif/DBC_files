# Предварительная карта прототипов T11

## Метод

Сопоставлены целевые наборы из запроса и фактические строки `visual_candidates.csv`. Ключи источника — `source_itemset_id` + слот; отображение — `Item.dbc.DisplayInfoID` → `ItemDisplayInfo.dbc.ID`; имя и слот сверены с `item_template.sql`. Для каждого выбранного T5-кандидата записан T4-кандидат того же класса/архетипа и слота. Armor subclass проверяется числом: cloth=1, leather=2, mail=3, plate=4; `Item.dbc` class должен быть 4 (Armor).

T5 стоит первым лишь как предварительный тай-брейк по близости тира к T11. Это не вывод о внешнем виде. T4-кандидат оставлен явно. Каждая строка имеет `visual_status=UNVERIFIED`; ни один DisplayID не трактуется как доказательство внешнего вида.

## Сводка

- В реестре 19 утверждённых комплектов × 5 слотов = 95 строк.
- Для 17 комплектов (85 строк) есть класс- и броне-совместимая T4/T5-кандидатура с реальными ItemSet/Item/DisplayInfo записями.
- Для двух Death Knight комплектов (10 строк) T4/T5-прототип не назначен: класс появился после эпохи T4/T5. Статус `UNRESOLVED`; следующий поиск — среди существующих WotLK DK plate предметов. Пока такая альтернатива не назначена.
- В каталоге 34 T4/T5 ItemSet-записи, охватывающие все пять целевых слотов для рассматриваемых классов. Это подтверждает наличие записей, но не визуальную пригодность.

## Совпадения между специализациями

- **Druid:** три записи Nordrassil (641/642/643) имеют один и тот же набор DisplayID по каждому слоту; то же для трёх Malorne (638/639/640). Поэтому один представитель применяется ко всем трём целевым специализациям. Отличающиеся названия исходных предметов не превращены в искусственное визуальное разнообразие.
- **Paladin:** Crystalforge (627/628/629) имеют совпадающие DisplayID по слотам; Justicar (624/625/626) также совпадает. Для всех трёх специализаций записан один представитель.
- **Warrior:** Destroyer Armor/Battlegear (656/657) и Warbringer Armor/Battlegear (654/655) совпадают по DisplayID для каждого слота. Для Arms/Fury и Protection использован общий представитель.
- **Priest:** Avatar Raiment/Regalia (665/666) совпадают по четырём слотам тела, а DisplayID головы различается. Incarnate Raiment/Regalia (663/664) совпадают по четырём слотам, а DisplayID перчаток различается.
- **Shaman:** T5 Cataclysm-варианты делят DisplayID chest, hands и shoulders; head различается у всех трёх, legs совпадают у Regalia/Harness и отличаются у Raiment. T4 Cyclone-варианты имеют одинаковые DisplayID по слотам.

Это сравнение ссылок и полей DBC. Совпадающий DisplayID означает ссылку на одну запись ItemDisplayInfo, но утверждение о фактически одинаковом отображении на персонаже требует просмотра клиента.

## Пробелы и спорные места

1. **Выбор T5 вместо T4 — временная конвенция**, основанная только на близости тира, не на визуальном сходстве с целевым T11. Если при ручном просмотре T4 подходит лучше, основание не запрещает выбрать T4.
2. **DK:** проверить реальные WotLK class-tier/plate предметы, затем подтвердить их ItemSet, ItemID, DisplayID и ItemDisplayInfo. Пока не переносить на DK модели Warrior/Paladin только из-за plate subclass.
3. **Распакованные ресурсы:** у T4/T5 кандидатов в предыдущем каталоге нет подтверждённого loose `.m2`/`.blp` совпадения. Это не означает, что ресурса нет в клиенте: MPQ не проверялись.
4. **Визуальная проверка:** `.m2`/`.blp` не просматривались. Не подтверждены цвет, геосеты, пропорции, совместимость с расой/полом/слотом и вид на персонаже.
5. **Класс/специализация исходных T4/T5 вариантов** распознаны по названиям семейств и раскладке set records. Их числовое членство и броневой subclass подтверждены данными; функциональная/визуальная специализация исходных моделей остаётся семантической классификацией.
6. **Альтернативы WotLK для остальных классов** не перечислялись: T4/T5 уже дают кандидата в каждом слоте, а внешний вид ещё не просмотрен. Возвращаться к WotLK альтернативам следует там, где просмотр покажет непригодность T4/T5.

## Контроль

- 19 целевых имён и специализаций перенесены из задания без переименования.
- Для каждого комплекта ровно Head, Shoulders, Chest, Hands, Legs.
- Для каждой provisional строки первичный и T4 ItemID существуют в исходном `visual_candidates.csv`; DisplayID и поля модели/текстур скопированы из этой записи.
- Все позиции помечены `UNVERIFIED`; DK-позиции остаются `UNRESOLVED`.
- Клиент, сервер, DBC, SQL и база данных не менялись; MPQ не извлекались.
