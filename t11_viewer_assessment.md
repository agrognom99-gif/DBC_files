# Оценка Vlad-s-Model-Viewer для аудита T11

Дата проверки: 2026-10-20. Режим: исследование опубликованной документации/репозитория и локальных путей. Программа не скачивалась и не запускалась.

## Краткий вывод

Кандидат заявляет цель 3.3.5a и чтение MPQ через StormLib, поэтому по заявленным функциям он потенциально подходит для первичного просмотра клиентских ресурсов. Однако сейчас его нельзя считать надёжно проверенным инструментом: точная совместимость с client build 12340 не подтверждена; репозиторий содержит готовый EXE и библиотеки Qt, но на видимой странице нет исходников; официальных Releases нет; существует открытая проблема, где автор сообщения указывает на падение при просмотре любого ресурса. Рекомендация: **не продолжать с этим исполняемым файлом; сначала проверить другой инструмент с доступным исходным кодом/воспроизводимым релизом и проверить его legacy-MPQ viewport-блокер.** ВладViewer оставить кандидатом второго круга после получения проверяемого источника и разрешённого изолированного теста.

## 1. Поддерживаемые версии WoW

README описывает viewer как сфокусированный на WoW 3.3.5a (Wrath of the Lich King) и private-server content. Это подтверждает заявленную поддержку ветки WotLK, но не перечисляет build ID. Поддержка именно **3.3.5a build 12340 — UNVERIFIED**: документального указания на этот build нет, фактический запуск не выполнялся.

Источники: [README кандидата](https://github.com/VladProject/Vlad-s-Model-Viewer), корень показывает содержимое репозитория и README.

## 2. Legacy MPQ или CASC

README прямо заявляет чтение MPQ-архивов через StormLib, выбор корня клиента с подкаталогом `Data\`, сканирование списка файлов в каждом архиве и поддержку дополнительных patch-папок. Это явное заявление о legacy MPQ; кандидат не описывает себя как CASC-only. Реальная загрузка конкретного набора архивов и корректный порядок patch/locale при build 12340 **UNVERIFIED** до теста.

Функция bulk MPQ extraction указана как возможность. Для настоящего аудита её следует не вызывать; текущая задача не разрешает извлечение.

## 3. ItemDisplayInfo и поиск предметов

В проверенном README отсутствует описание чтения `ItemDisplayInfo.dbc`, алгоритма разрешения Item ID → DisplayID → модели/текстуры или импорта предметов из AzerothCore CSV. На странице кандидата не видны исходные файлы реализации. Следовательно:

- разрешение предмета по Item ID / `ItemDisplayInfo.dbc`: **UNVERIFIED**;
- загрузка по DisplayID или имени файла: **UNVERIFIED**;
- использование конкретных путей `ItemDisplayInfo.dbc` из клиента: **UNVERIFIED**;
- показ элементов экипировки по базе предметов/CSV: **UNVERIFIED**.

Не следует считать, что просмотр файлового дерева модели эквивалентен отображению конкретного предмета: связь с DBC и вариантами текстур нужно подтвердить отдельно.

## 4. Персонаж, экипировка, геосеты, текстуры

README обещает просмотр игровых ассетов и WMO, но найденное описание не подтверждает экипировку предмета на персонаже, настройку race/gender, armor geosets, скрытие шлема/плеч, geoset-комбинации или корректность наложения текстур/альфа-каналов. Все эти функции **UNVERIFIED**. Нельзя утверждать визуальную пригодность модели для T11, пока конкретный предмет не просмотрен на персонаже с проверкой соответствующих слотов и геосетов.

## 5. Известные ограничения и признаки риска

- GitHub показывает три коммита; Releases отсутствуют. Репозиторий на дату просмотра содержит `VladModelViewer.exe`, DLL Qt 6 и runtime-папки, но в корне не отображает исходники. Это ограничивает аудит бинарника и воспроизводимость сборки.
- Открыт issue **“Any asset = crash”**. Автор сообщает, что попытка просмотреть любой ассет приводит к падению также на свежем WotLK-клиенте; причина в issue не установлена. Это не доказывает, что сбой повторится здесь, но делает запуск отдельным риском.
- Не обнаружено опубликованного release asset со стабильной версией/заметками и контрольной суммой/подписью. Подлинность и соответствие доступному исходному коду не подтверждены.
- README позиционирует проект как персональную улучшенную версию WMV. Небольшая история репозитория и отсутствие видимых исходников сами по себе не доказывают небезопасность, но существенно снижают проверяемость.

Источники: [файлы/история репозитория](https://github.com/VladProject/Vlad-s-Model-Viewer), [страница Releases](https://github.com/VladProject/Vlad-s-Model-Viewer/releases), [открытый issue](https://github.com/VladProject/Vlad-s-Model-Viewer/issues/1).

## 6. Файлы, создаваемые при запуске

README указывает, что при первом запуске рядом с EXE создаются:

| Путь относительно EXE | Заявленное назначение |
|---|---|
| `cache/` | индекс файлов архива для последующих запусков |
| `logs/wmvx.log` | журнал |
| `logs/crashes/` | дампы и crash log |
| `screenshots/` | скриншоты по F10 |
| `userSettings/log.txt` | журнал интеграции Noggit |
| `export/` | вывод bulk MPQ extraction |
| `settings.ini` | настройки |
| `favorites.json` | избранные файлы |

Это означает, что запуск EXE из клиентского каталога может писать рядом с ним. Не запускать его из `E:\Games\WoW_3.3.5_12340` и не помещать EXE туда. README не описывает отдельные флаги/настройки переноса каждого runtime-пути или режим, гарантирующий нулевые записи клиента.

## 7. Можно ли указать клиент только для чтения и отделить runtime-файлы

README предлагает выбрать корень клиента и заявляет прямое чтение MPQ без изменения клиента. Это не является технической гарантией read-only доступа к файлам: отсутствие записи в клиент нужно проверить наблюдением за файловыми операциями. Поскольку runtime-данные пишутся рядом с EXE, разумная будущая схема — держать viewer в отдельном каталоге аудита, например `T11-Audit\viewer-sandbox`, и направить picker на `E:\Games\WoW_3.3.5_12340`. **Эта схема пока не проверена**, включая то, что клиент остаётся без изменений и все кэш/логи/скриншоты действительно остаются рядом с EXE.

На момент проверки в `T11-Audit` и корне клиента `VladModelViewer.exe` не обнаружен. Никакая программа не запускалась.

## 8. Происхождение бинарника и соответствие исходникам

Проверенная GitHub-страница показывает EXE как файл репозитория, лицензию GPL-3.0 и README, но не показывает source tree; список Releases пуст. Поэтому сейчас нельзя сопоставить официальный релиз с конкретным commit/source build. До будущего теста необходимо:

1. Установить точный commit SHA и происхождение именно того артефакта, который будет тестироваться; не брать бинарник из сторонних зеркал.
2. Убедиться, что исходники реализации доступны на конкретном commit и что лицензия/third-party компоненты зафиксированы.
3. Проверить опубликованные checksum/signature (если появятся); если их нет — вычислить SHA-256 локального артефакта до запуска и занести его в журнал, понимая, что хеш фиксирует файл, но сам по себе не подтверждает автора.
4. Проверить Authenticode-подпись штатным `Get-AuthenticodeSignature`; отсутствие подписи не равно доказательству вредоносности, но подпись должна быть проверяема, если на неё опираются.
5. Если доступна сборка из исходников, оценить воспроизводимость и соответствие бинарника исходному commit. Сборку не проводить в рамках текущего этапа.
6. Не запускать EXE, пока открытый crash issue и происхождение артефакта не рассмотрены.

## Локально доступное

По ранее собранной локальной инвентаризации клиент `E:\Games\WoW_3.3.5_12340` содержит loose DBC, некоторые распакованные ресурсы и MPQ в `Data`. Клиентские утилиты карт/vmap не являются просмотрщиком экипировки. В текущей проверке локально ни `VladModelViewer.exe`, ни его установка не найдены. Сам клиент не изменялся.

### Рекомендация

**Сначала проверить другой инструмент с доступным исходным кодом/происхождением.** WMVx — более проверяемый исходный проект и заявляет поддержку WotLK 3.3.5, но его README перечисляет WotLK-ограничения по текстурным анимациям/прозрачности, а отдельный актуальный viewport-блокер для legacy MPQ следует сверить перед выбором. Vlad-s-Model-Viewer можно вернуть в короткий список только после прояснения crash issue, источника EXE и способа гарантированно изолировать записи.
